## Sobre o projeto

O **TrilhaDoDev** é um projeto open source de estudo colaborativo cujo propósito é **organizar o aprendizado em desenvolvimento de software** de forma progressiva, prática e acessível a pessoas de diferentes níveis.

O repositório reúne **guias, trilhas de aprendizagem, aulas e estruturas para exercícios e projetos**. Em vez de ser apenas uma coleção de links, o TrilhaDoDev propõe uma **jornada de aprendizagem estruturada**: cada trilha indica o que estudar, em que ordem e com quais materiais práticos.

### Motivação e objetivos

Muitas pessoas que começam a estudar programação se deparam com excesso de conteúdo disperso e falta de direção. O TrilhaDoDev existe para reduzir esse ruído por meio dos seguintes objetivos:

- **Organizar o aprendizado por áreas e níveis**, evitando sobrecarga e lacunas.
- **Explicar conceitos com linguagem clara e exemplos práticos**, priorizando o “aprender fazendo”.
- **Incentivar a prática** com aulas, exercícios e projetos.
- **Criar um espaço aberto para colaboração**, onde a comunidade possa corrigir, expandir e compartilhar conhecimento.

O projeto está em construção: algumas áreas já possuem aulas completas, enquanto outras mantêm uma estrutura inicial pronta para receber novas contribuições.

---

## Para quem é este projeto

O TrilhaDoDev foi pensado para:

- **Pessoas iniciantes** que querem um caminho claro para começar em desenvolvimento web e programação.
- **Pessoas em transição de carreira** que precisam consolidar fundamentos de forma organizada.
- **Estudantes autodidatas** que buscam material em português, com progressão lógica e prática.
- **Contribuidores** que desejam compartilhar conhecimento e ajudar a construir uma referência aberta em português.

> **Não é necessário conhecimento prévio em programação** para começar pelas trilhas iniciais. O projeto assume que a pessoa sabe usar um editor de texto e navegar por arquivos, mas não exige experiência com código.

## Como começar (guia rápido)

O TrilhaDoDev é um repositório **baseado em Markdown**. Não há dependências para instalar, servidor para executar ou configuração de ambiente obrigatória. O “quick start” consiste em acessar o conteúdo e começar a estudar.

### 1. Acesse o conteúdo

- **No GitHub:** navegue diretamente pelos links deste README. Os arquivos `.md` são renderizados automaticamente.
- **Localmente:** clone o repositório (opcional, para quem quiser explorar offline ou contribuir):

  ```bash
  git clone https://github.com/MessiasLim/TrilhaDoDev.git
  ```

- Abra a pasta no seu editor de texto ou IDE de preferência (VS Code, por exemplo).
- Para visualizar a formatação, use o **preview de Markdown** do editor (`Ctrl+Shift+V` no VS Code, por exemplo).

### 2. Escolha um ponto de partida

Se você está começando do zero em desenvolvimento web, a ordem sugerida é:

1. Leia [**Como estudar**](./Guias/como-estudar.md) para organizar sua rotina.
2. Consulte os [**Fundamentos de Frontend**](./Trilhas/Frontend/Fundamentos/README.md).
3. Estude as aulas de [**HTML**](./Trilhas/Frontend/Fundamentos/HTML/) e [**CSS**](./Trilhas/Frontend/Fundamentos/CSS/).
4. Pratique com as aulas de [**JavaScript**](./Trilhas/Linguagens/JavaScript/).
5. Escolha uma **trilha complementar** (Backend, Banco de dados, DevOps, etc.) conforme seus objetivos.

### 3. Pré-requisitos

- **Para estudar:** nenhum software especial além de um editor de texto e um navegador. Um editor com suporte a Markdown (como VS Code) melhora a experiência.
- **Para contribuir:** é recomendável ter noções básicas de **Git e GitHub**. Se precisar, consulte o guia [**Como usar Git e GitHub**](./Guias/como-usar-git-e-github.md). Também é útil conhecer a sintaxe **Markdown** - há um guia no diretório [Guias](./Guias/README.md).

## Sugestão de percurso para iniciantes

Se você está começando e não sabe exatamente por onde ir, esta é uma sequência testada e recomendada. Ela assume que você tem **de 5 a 10 horas por semana** para estudar.

| Etapa | Foco | Material sugerido | Tempo estimado |
| --- | --- | --- | --- |
| 1 | Organização e método de estudo | [Como estudar](./Guias/como-estudar.md) | 1–2 h |
| 2 | Fundamentos de Frontend (visão geral) | [Fundamentos de Frontend](./Trilhas/Frontend/Fundamentos/README.md) | 2–3 h |
| 3 | HTML | [Aulas de HTML](./Trilhas/Frontend/Fundamentos/HTML/) | 8–12 h |
| 4 | CSS | [Aulas de CSS](./Trilhas/Frontend/Fundamentos/CSS/) | 8–12 h |
| 5 | JavaScript (introdução) | [Aulas de JavaScript](./Trilhas/Linguagens/JavaScript/) | 12–20 h |
| 6 | Prática com projeto próprio | Crie uma página simples usando HTML, CSS e JS | 5–10 h |
| 7 | Versionamento | [Como usar Git e GitHub](./Guias/como-usar-git-e-github.md) | 3–5 h |
| 8 | Escolha de trilha complementar | Backend, Banco de dados, DevOps, etc. | - |

> **Importante:** este percurso é uma **sugestão**, não uma regra. Sinta-se livre para adaptar a ordem e o ritmo ao seu contexto. O mais importante é **praticar regularmente** e não acumular apenas teoria.

## Como usar este repositório

### Para estudantes

1. **Navegue pelas trilhas** usando os links deste README ou os READMEs internos de cada diretório.
2. **Leia uma aula por vez** e, em seguida, **reproduza os exemplos** no seu próprio editor.
3. **Registre dúvidas e exercícios** em um projeto pessoal (um repositório no GitHub, por exemplo). Isso ajuda a fixar o conteúdo e cria portfólio.
4. **Consulte os guias** sempre que precisar de apoio sobre método de estudo ou ferramentas.
5. **Não pule etapas**: os fundamentos de HTML, CSS e JavaScript são a base para qualquer trilha avançada.

### Para contribuidores

1. Leia o [**Guia de contribuição**](./CONTRIBUTING.md) e o [**Código de conduta**](./CODE_OF_CONDUCT.md).
2. Verifique o [**modelo de conteúdo (`TEMPLATE.md`)**](./TEMPLATE.md) antes de criar uma nova aula ou guia.
3. Escolha uma trilha em expansão ou uma lacuna no conteúdo existente.
4. Abra uma **issue** para discutir sua proposta antes de enviar um **pull request** (especialmente para conteúdos extensos).
5. Siga as boas práticas de escrita: linguagem clara, exemplos práticos, links funcionais e formatação Markdown consistente.

> A contribuição não se limita a escrever aulas. **Correções de erros, melhorias na redação, sugestões de links e ajustes na estrutura também são muito valiosas.**

## Como contribuir

Contribuições de todos os tipos são bem-vindas: correções, melhorias, novas aulas, exercícios, sugestões de trilhas e ajustes na documentação.

### Passos básicos

1. **Leia** o [CONTRIBUTING.md](./CONTRIBUTING.md) - ele contém detalhes sobre padrões de escrita, formatação e fluxo de trabalho.
2. **Consulte** o [TEMPLATE.md](./TEMPLATE.md) para manter a consistência dos novos materiais.
3. **Verifique** se já existe uma issue ou pull request relacionado ao que você pretende fazer.
4. **Abra uma issue** (se necessário) para alinhar a proposta com os mantenedores.
5. **Envie um pull request** com uma descrição clara do que foi alterado e por quê.

### O que você pode contribuir

- Correções de erros de português, formatação ou links quebrados.
- Melhorias na clareza das explicações.
- Novos exercícios e projetos práticos.
- Aulas completas para trilhas em expansão.
- Guias de apoio (ex.: “como instalar o VS Code”, “como usar o terminal”).
- Traduções (se o projeto decidir oferecer versões em outros idiomas no futuro).

> **Pull requests e issues são incentivados.** Para dúvidas, sugestões ou propostas de melhoria, abra uma issue no [repositório no GitHub](https://github.com/MessiasLim/TrilhaDoDev).

## FAQ - Perguntas frequentes

<details>
<summary><strong>1. Preciso saber programar para usar o TrilhaDoDev?</strong></summary>

Não. As trilhas iniciais (Frontend e JavaScript) foram pensadas para quem está começando do zero. Se você já tem experiência, pode pular para as trilhas em expansão ou contribuir com conteúdo avançado.

</details>

<details>
<summary><strong>2. Preciso instalar algo para estudar?</strong></summary>

Não. Todo o conteúdo é em Markdown e pode ser lido diretamente no GitHub ou em qualquer editor de texto. Para praticar os exemplos, você vai precisar de um navegador e, para JavaScript, de um ambiente como o console do navegador ou o Node.js.

</details>

<details>
<summary><strong>3. Como faço para contribuir se nunca usei Git?</strong></summary>

Consulte o guia [Como usar Git e GitHub](./Guias/como-usar-git-e-github.md). Ele cobre desde a instalação até o envio de um pull request. Se ainda tiver dúvidas, abra uma issue pedindo ajuda - a comunidade está aqui para isso.

</details>

<details>
<summary><strong>4. O conteúdo é atualizado com que frequência?</strong></summary>

O projeto está em construção ativa. Algumas trilhas recebem atualizações frequentes; outras aguardam contribuições. Você pode acompanhar as mudanças pelo [CHANGELOG.md](./CHANGELOG.md).

</details>

<details>
<summary><strong>5. Posso usar o conteúdo em aulas, cursos ou materiais próprios?</strong></summary>

Sim, desde que respeitados os termos da [licença MIT](./LICENSE). Em resumo: você pode usar, copiar, modificar e distribuir, desde que mantenha o aviso de copyright e a permissão. Para usos educacionais, é recomendável citar a fonte.

</details>

<details>
<summary><strong>6. Encontrei um erro. Como reportar?</strong></summary>

Abra uma issue descrevendo o erro e, se possível, o link para o arquivo e a linha. Se você souber corrigir, pode enviar um pull request diretamente.

</details>

<details>
<summary><strong>7. O projeto aceita sugestões de novas trilhas?</strong></summary>

Sim. Abra uma issue com sua sugestão. Trilhas em expansão já estão mapeadas, mas novas ideias são bem-vindas se estiverem alinhadas ao propósito educacional do projeto.

</details>
